## What 0.3.0.0 adds (over 0.2.0.0)

- **Full lineup** (`Guide/Channels/lineup.json` + `pools-seed.json`,
  generated by `plugin/tools/gen-lineup-0.3.0.0.py` from the live
  sidecar pools + the 1,304-item catalog; report
  `plugin/BUILD-0.3.0.0-LINEUP-REPORT.md`): **155 defs, 153 seed pool
  channels, 2,982 items**, sidecar numbers 1–216, both tiers live
  (98 PD / 57 user-uploaded channels). 72 channels are
  catalog-refreshable (dominant catalog folder + title/genre/year
  match); 81 are refresh-frozen (Folder = own channel name, so a
  catalog refresh leaves their seed pools untouched).
- **Commercial breaks** (`Guide/ScheduleEngine.cs` CommercialBreaks +
  `GuideService` wiring + config-page toggle): a direct port of the
  sidecar v0.2.0 engine — same constants, same FNV-1a spot pick, same
  greedy boundaries + repeat-boundary guard. At most ONE break per
  hour per channel, one 30–60 s vintage spot, programme boundaries
  only, from the same 66-spot pool (40 in the 30–60 s range). Breaks
  interleave into the channel's effective item list, so the guide
  (XMLTV + JSON) and the live stream (ffmpeg batch) can never
  disagree. Toggle on the settings page, **default ON**, server-wide,
  no restart needed. Excluded: Ad Break, Ads 1950s/1960s/1970s,
  Station Break, Audiobooks (+ the synthetic weather channel).
- **96 h guide window** (was 48 h): XMLTV, guide JSON, and the
  `Guide/Data` endpoint all default to 96 h (clamp 1–96). Jellyfin
  refreshes every 48 h, so each refresh re-sends ~48 h of overlap —
  no gaps even if a refresh runs late.
- **Additive catalog refresh**: `RefreshPoolsFromCatalog` now MERGES
  by identifier (tier-aware) — catalog items are added or refresh the
  matching pool entry; nothing is ever removed. A catalog build can
  only grow the guide. (0.2.0.0 replaced the pools outright, which
  would have dropped every channel the catalog can't fill.)
- **Config page**: Commercial Breaks checkbox (default ON when unset).
- **README** updated to 0.3.0.0 (155 channels, 96 h, breaks, manual
  package instructions, build.sh warning).

## Known limitations / notes

- The guide JSON for 96 h is ~36 MB (154 channels × 96 h); the
  guide page only asks for 2 h, so the page itself is unaffected.
- The 1-minute throttle on weather forecast attempts means the first
  Guide/Weather call after a fresh install (or after saving
  coordinates) can still read "unavailable" while the background
  refresh is in flight; the next call shows live data. Pre-existing
  0.2.0.0 behavior, unchanged.
- The pilot build's 12 items joined 69 (channel, item) pairs on the
  merge — an item can match several channels (folder + title
  keywords), which is by design.
- Nothing was deleted. The sidecar's work, the full-catalog files,
  and the 0.2.0.0 test server backup were not touched.
